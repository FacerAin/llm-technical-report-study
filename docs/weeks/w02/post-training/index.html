§3–§3.2는 사람 선호를
모델 개선으로 바꾸는 과정입니다

Llama 2-Chat의 후학습은 사람이 만든 데이터 두 종류로 시작합니다. 사람이 직접 쓴 답(SFT)과 사람이 두 답 중 고른 결과(선호)입니다.

Meta는 직접 쓴 답을 2.7만 건에서 멈추고, 나머지 예산을 141만 건의 비교로 돌렸습니다. 그 비교로 reward model 두 개를 학습하고, RS와 PPO로 모델을 다섯 번 고쳤습니다.

왜 2만 7천 건에서 멈췄을까요. 180건을 직접 비교해 보니 모델이 쓴 답이 사람이 쓴 답과 비슷했습니다. 그러면 사람이 답을 더 써 줘도 모델이 그 이상 나아지기 어렵습니다. 그래서 예산을 고르는 쪽으로 옮겼습니다. 저자들은 5.1절에서, 사람은 잘 쓰지는 못해도 두 답 중 나은 쪽은 잘 고른다는 점을 RLHF의 강점으로 듭니다.

SFT loss는
답 토큰에서만 계산합니다

학습셋의 prompt와 답을 이어 붙여 4,096 토큰을 채우고, prompt와 답 사이에 special token(S)을 둡니다.

다음 토큰 예측은 그대로지만 user prompt 토큰의 loss를 0으로 둡니다. 모델이 배울 것은 질문하는 말투가 아니라 답하는 방식이기 때문입니다(일반적 설명, 원문은 이유 미기술).

원문에 없는 것이어 붙인 앞 샘플을 뒤 샘플이 attention으로 볼 수 있는지(문서 경계 마스킹)는 미기술입니다.
근거: Llama 2 · §3.1 Fine-Tuning Details
학습 방식은 사전학습과 같은 다음 토큰 예측인데, 차이가 하나 있습니다. prompt 부분은 loss를 0으로 두고, 답 부분에서만 loss를 계산합니다. 여러 샘플을 4,096 토큰 길이로 이어 붙여 학습하는데, 이때 앞 샘플이 뒤 샘플에 보이는지는 원문에 나와 있지 않습니다.

SFT 학습률은
사전학습 peak의 약 1/15입니다

수집 절차는 네 단계입니다. annotator가 질문을 쓰고, 서로 다른 모델에서 뽑은 두 응답 중 하나를 고르고, 얼마나 더 나은지를 네 단계로 표시합니다. 두 응답을 일부러 다른 모델, 다른 온도에서 뽑아서 차이가 크게 나도록 했습니다.

왜 여러 개 순위를 매기지 않고 두 개만 비교했을까요. 저자들은 prompt 다양성을 이유로 듭니다. 순위 방식은 한 질문에서 많은 쌍을 얻지만, 그만큼 다양한 질문을 덜 보게 됩니다. 대신 이진 비교는 두 응답이 비슷해지면 고르기 어려워진다는 약점이 있습니다.

도움과 안전은 기준이 충돌해서
지침을 나눠 따로 모았습니다

도움됨은 요청을 얼마나 잘 들어주고 정보를 주는가, 안전은 응답이 안전 지침에 비추어 위험한가입니다.

"폭탄 만드는 법을 자세히"는 도움은 되지만 안전하지 않습니다. 한 기준으로 섞으면 판단이 흔들리므로, 지침을 나눠 각각 맞는 지시를 줍니다. 안전 annotator는 적대적 prompt에 집중합니다.
