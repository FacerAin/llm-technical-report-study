2-1 · §5.1 SFT

Reasoning Data: R1을 그대로 쓸 수 없었던 이유

SFT 데이터는 1.5M instances, 도메인마다 만드는 방법이 다릅니다. Reasoning 쪽이 가장 공들인 부분입니다.

R1이 생성한 reasoning 데이터

정확도는 강하다 (strong accuracy)

그런데 — overthinking · poor formatting · excessive length

vs
일반 형식의 reasoning 데이터

명료하고 간결하다 (clarity and conciseness)

대신 정확도는 R1만 못하다

저자의 목표
둘을 balance — R1의 정확도는 가져오고 장황함은 버린다. 다음 장이 그 방법입니다.
근거: DeepSeek-V3 §5.1 (p.28)Post-training · Reasoning Data 문제의식
근거 · 2-1
“We curate our instruction-tuning datasets to include 1.5M instances spanning multiple domains, with each domain employing distinct data creation methods tailored to its specific requirements.”DeepSeek-V3 §5.1 (p.28)
“For reasoning-related datasets, including those focused on mathematics, code competition problems, and logic puzzles, we generate the data by leveraging an internal DeepSeek-R1 model. Specifically, while the R1-generated data demonstrates strong accuracy, it suffers from issues such as overthinking, poor formatting, and excessive length. Our objective is to balance the high accuracy of R1-generated reasoning data and the clarity and conciseness of regularly formatted reasoning data.”DeepSeek-V3 §5.1 Reasoning Data (p.28)

미기술 1.5M의 도메인별 구성 비율, R1 데이터의 분량은 적지 않았습니다.

제 파트는 아니지만 흐름상 SFT 데이터를 두 장 짚겠습니다. 전체 1.5M instances이고 도메인마다 만드는 방법이 다릅니다. 그중 reasoning, 즉 수학과 코드 경쟁 문제, 논리 퍼즐 데이터는 내부 R1 모델로 생성합니다. 문제는 R1이 만든 데이터가 정확도는 강한데 overthinking, 형식 불량, 과도한 길이라는 문제가 있다는 겁니다. 반대로 일반 형식의 reasoning 데이터는 명료하고 간결한데 정확도가 R1만 못합니다. 그래서 저자의 목표는 이 둘을 balance하는 것, R1의 정확도는 가져오고 장황함은 버리는 것입니다.
2-2 · §5.1 SFT

Expert model 파이프라인: 최종 SFT 데이터를 만드는 4단계

R1을 직접 쓰는 대신, 도메인별 expert model을 따로 만들어 그 모델로 데이터를 생성합니다.

단계무엇을 하나목적
① Expert model 구축code · mathematics · general reasoning 각 도메인에 SFT + RL 파이프라인으로 전용 모델 학습최종 모델용 data generator 확보
② 샘플 2종 생성instance마다 <problem, original response> 와 <system prompt, problem, R1 response>. system prompt는 reflection · verification 유도R1 방식과 원본 방식을 모두 노출
③ RL로 두 패턴 통합high-temperature sampling으로 두 패턴을 섞은 응답 생성. 수백 step 후 system prompt 없이도 R1 패턴 체득R1 패턴을 모델에 내재화
④ Rejection samplingRL 완료된 expert model을 생성원으로 고품질 데이터만 선별최종 SFT 데이터 = 정확 + 간결

DeepSeek-V3 §5.1 Reasoning Data (p.28) · 파랑 칸 = 발표자 강조 · Non-Reasoning은 DeepSeek-V2.5가 생성 + 사람이 검수(한 줄)

근거: DeepSeek-V3 §5.1 (p.28) Post-training · SFT 데이터 생성 파이프라인
근거 · 2-2

This expert model serves as a data generator for the final model.”DeepSeek-V3 §5.1 Reasoning Data (p.28)
“The training process involves generating two distinct types of SFT samples for each instance: the first couples the problem with its original response in the format of , while the second incorporates a system prompt alongside the problem and the R1 response in the format of . 그 방법이 이 네 단계입니다. 먼저 code, mathematics, general reasoning 각 도메인마다 SFT와 RL을 조합한 파이프라인으로 expert 모델을 따로 학습합니다. 이 expert 모델이 최종 모델용 데이터 생성기 역할을 합니다. 둘째로, 학습할 때 문제 하나마다 SFT 샘플을 두 종류 만듭니다. 하나는 문제와 원래 응답을 묶은 것, 다른 하나는 system prompt와 문제, 그리고 R1의 응답을 묶은 것입니다. 이 system prompt는 모델이 reflection과 verification을 하도록 유도하게 설계했습니다. 셋째, RL 단계에서 high-temperature sampling으로 두 패턴이 섞인 응답을 생성하게 하고, 수백 step이 지나면 system prompt가 없어도 R1 패턴을 쓰게 됩니다. 마지막으로 RL이 끝난 expert 모델을 생성원으로 rejection sampling을 걸어 고품질 데이터만 최종 SFT 데이터로 추립니다. 이렇게 해서 정확하면서 간결한 데이터를 얻는다는 겁니다. Non-reasoning 데이터는 창작이나 롤플레이, 단순 QA인데 V2.5가 생성하고 사람이 검수하는 것으로 간단합니다.

3-1 · Packing과 Attention

Attention masking: 여러 샘플을 한 줄에 묶으면, 샘플끼리 봐도 되나?

짧은 샘플을 패딩으로 채우면 계산이 아깝습니다. 그래서 여러 샘플을 이어 붙여 한 sequence를 채웁니다(packing). 문제는 그 다음입니다.

마스킹 없음

packing만 하고 attention은 그대로 둔다.

뒤 샘플 B의 토큰이 앞 샘플 A를 볼 수 있다.

vs
마스킹 적용 (sample masking)

샘플 경계에서 attention을 끊는다.

각 샘플이 독립 시퀀스처럼 보인다.

DeepSeek-V3 안에서도 답이 갈린다
사전학습(§4.1)과 SFT(§5.1)가 서로 다른 선택을 했습니다.

출처 전체

짧은 샘플을 패딩으로 채우면 계산이 아까우니 여러 샘플을 이어 붙입니다. 그런데 이어 붙이고 나면 뒤 샘플이 앞 샘플을 attention으로 볼 수 있습니다. 이걸 그대로 둘지, 경계에서 끊을지가 질문입니다. 그리고 DeepSeek-V3는 이 질문에 사전학습과 SFT에서 다른 답을 냅니다.

7-1 · 정리

정리: 단순한 SFT로 오픈모델 1위, 그런데 masking은 단계마다 다르게

오늘 내용을 세 줄로 줄이면 이렇습니다.

① SFT는 단순하다
1.5M · 2 epoch · lr 5×10⁻⁶ → 1×10⁻⁶ · 후학습 비용 5K GPU hours (전체의 약 0.18%)
② packing + masking은 단계마다 다르다
해석 사전학습은 막지 않고 SFT는 막는다 · 다른 논문들은 대체로 막는 쪽이 유리하다고 본다
③ Base · Chat 모두 오픈모델 최고
Base 31개 중 22개 · Chat 오픈모델 대비 22개 중 20개 최고 · 약점은 SimpleQA · SWE-Bench
