# W04 Post-training 발표 대본

## @overview
제 파트는 두 보고서의 Post-training입니다. 오늘 강조하고 싶은 건 두 가지입니다. Qwen2.5는 SFT 확장으로, Qwen2 대비 데이터를 50만에서 100만 이상으로 늘리고 영역을 넓혔습니다. Qwen3는 thinking mode와 thinking budget으로, 한 모델에서 생각을 켜고 끄고 생각 길이까지 조절할 수 있게 됐습니다.

## @q25-intro
Qwen2.5 서두가 꼽는 진전은 두 가지입니다. 첫째, SFT 데이터를 100만 개 넘게 늘리고 긴 생성·수학·코드 같은 아홉 영역을 다룹니다. 둘째, RL을 둘로 나눴습니다. 기준은 보상 모델이 채점할 수 있느냐입니다. 추론이나 사실성처럼 RM이 채점하기 어려운 건 정답이 있는 데이터로 DPO를 하고, 간결함·무해함처럼 미묘한 품질은 RM을 써서 GRPO로 올립니다.

## @q25-sft-areas
SFT 데이터를 넓힌 아홉 영역입니다. Qwen2의 SFT는 지시 따르기, 코딩, 수학, 논리, 롤플레이, 다국어, 안전의 일곱 능력을 다뤘습니다. 이와 비교하면 주황색 세 개가 새로 생겼습니다. 출력을 8K까지 늘린 긴 생성, 표나 JSON 같은 구조화 데이터 이해, 다양한 system prompt에도 일관되게 답하는 능력입니다. 응답 필터는 Qwen2에도 있었지만, Qwen2는 수학은 정답 확인, 코드는 실행, 나머지는 사람이 순위를 매기는 식으로 영역마다 따로 걸렀습니다. Qwen2.5는 여기에 전용 critic model과 여러 에이전트의 채점을 모든 답에 공통으로 한 번 더 씌우고, 모든 채점기를 통과한 답만 남깁니다. 파란색은 기존 영역을 키운 것으로, 수학과 코드는 Math · Coder 모델 데이터를 가져왔고, 다국어는 고자원 언어 능력을 저자원 언어로 옮기는 쪽으로 확장했습니다.

## @q25-sft
SFT 설정은 Qwen2와 똑같습니다. 32K 길이로 2 epoch, 학습률은 7e-6에서 7e-7로 줄이고, weight decay 0.1, gradient clipping 1.0입니다. 바뀐 건 데이터뿐으로, 50만 개에서 100만 개 이상으로 약 두 배 늘었습니다. W02의 Llama 2와 비교하면 예시 수는 약 40배, 길이는 8배입니다.

## @q25-t6
Table 6은 Instruct 모델 비교입니다. 72B는 다섯 배 큰 Llama 3.1 405B를 13개 중 7개에서 앞서고, 본문이 이름을 든 7개가 정확히 그것입니다. 특히 MATH, LiveCodeBench, Arena-Hard 차이가 큽니다. Plus는 72B를 9개에서 앞섭니다.

## @reasoning-timeline
Qwen3를 보기 전에 시대 배경을 짚겠습니다. 2022년에는 단계별로 생각하라는 프롬프트만으로 추론이 좋아진다는 게 알려졌습니다. 전환점은 2024년 9월 OpenAI o1입니다. RL로 길게 생각하도록 학습했고, 생각 시간을 늘릴수록 성능이 오른다고 밝혔습니다. 모델을 키우는 것 말고 추론 때 계산을 더 쓰는 새 축이 열린 겁니다. 이후 QwQ와 DeepSeek-R1이 오픈 진영에서 따라왔고, 2025년 초 Claude 3.7과 Gemini 2.5는 한 모델에서 thinking을 켜고 끄는 방식으로 갔습니다. Qwen3는 이 하이브리드 방식을 오픈 가중치로 낸 모델입니다.

## @q3-pipeline
Qwen3로 넘어갑니다. 목표는 두 가지입니다. 사용자가 생각 여부와 길이를 정하는 Thinking Control, 그리고 작은 모델을 싸게 만드는 증류입니다. 플래그십만 네 단계를 거칩니다. 1, 2단계에서 생각하는 능력을 만들고, 3, 4단계에서 바로 답하는 능력과 일반 능력을 더합니다. 작은 모델은 이 과정을 다시 하지 않고 플래그십을 교사로 증류합니다. 예비 실험에서 증류가 네 단계 학습보다 Pass@1, Pass@64 모두 높았고 GPU 시간은 10분의 1이었습니다.

## @cs-filter
Cold Start 데이터는 네 단계로 만듭니다. 먼저 정답이나 테스트 케이스가 붙은 수학, 코드, 논리, STEM 문제를 모읍니다. 그래서 답이 맞았는지 자동으로 확인할 수 있습니다. 다음은 문제 필터입니다. Qwen2.5 72B Instruct로 정답 판정이 애매한 문제를 빼고, 특히 생각 없이도 맞히는 쉬운 문제를 뺍니다. 생각해야만 풀리는 문제만 남기려는 겁니다. 세 번째는 풀이 필터입니다. QwQ 32B로 문제마다 풀이를 N개 뽑습니다. 계속 못 푸는 문제는 사람이 직접 확인하고, 하나라도 맞힌 문제는 풀이 중에서 오답, 반복, 찍기, 생각과 요약이 안 맞는 것, 언어가 섞인 것, 검증셋과 비슷한 것을 버립니다. 버리는 단위는 문제가 아니라 풀이입니다. 마지막으로 걸러낸 것 중 일부만 짧게 학습합니다. 목표는 점수가 아니라 추론 패턴만 심는 것이고, 여기서 성능까지 맞추면 다음 RL에서 더 오를 여지가 줄어든다는 게 저자들의 이유입니다. 다만 실제 샘플 수나 이를 보여주는 실험은 없습니다.

## @rl-reasoning
Stage 2 Reasoning RL은 흐름만 짚겠습니다. Cold Start에 쓰지 않았고, 배울 수 있으면서도 최대한 어려운 문제 3,995개로 GRPO를 돌립니다. GRPO는 문제 하나에 답을 여러 개 뽑아 채점하고, 그룹 평균보다 나은 답은 강화하고 못한 답은 약화하는 방식입니다. 문제는 원문 4조건을 만족해야 합니다. Cold Start에 안 쓴 것, Cold Start 모델이 배울 수 있는 것, 최대한 어려운 것, 하위 도메인이 넓은 것입니다. 235B 기준 AIME'24가 170 step 만에 70.1에서 85.1로 올랐습니다. 32B를 보면 Stage 2 뒤 AIME는 이미 최종 점수 수준입니다. 반면 IFEval과 CounterFactQA는 아직 낮고, 이 부분을 Stage 3과 4가 채웁니다.

## @q3-modes
이제 Stage 3 Thinking Mode Fusion입니다. Fusion 데이터를 보기 전에 무엇을 합치는지부터 보겠습니다. thinking 모드는 수 비교처럼 따져 봐야 하는 문제에서 think 블록 안에서 길게 생각하고 검산한 뒤 답합니다. non-thinking 모드는 번역처럼 바로 답하면 되는 일에서 think 블록을 비워 두고 곧장 답합니다. 예전에는 대화용 모델과 QwQ 같은 추론 전용 모델을 따로 썼는데, Qwen3는 Stage 3에서 이 둘을 한 모델에 합치고 질문 끝의 flag로 고르게 합니다.

## @tmf-data
Stage 2 모델 위에 SFT를 더 하는데, 데이터는 두 종류입니다. thinking 데이터는 Cold Start 때 쓴 문제를 다시 가져와 Stage 2 모델이 직접 풀이를 여러 개 만들고, 좋은 풀이만 남깁니다. 다른 모델 풀이가 아니라 자기 풀이로 배우기 때문에 SFT를 더 해도 RL로 올린 추론 실력이 유지됩니다. non-thinking 데이터는 코딩부터 롤플레이까지 7가지 태스크를 고르게 담았고, 답마다 자동으로 만든 체크리스트로 품질을 거릅니다. 저자원 언어를 위해 번역 비중도 일부러 늘렸습니다.

## @tmpl
학습 데이터 형식을 보면, 질문 끝에 /think나 /no_think flag를 붙이고, non-thinking 답에도 빈 think 블록을 남깁니다. 그러면 모든 답이 think 블록 다음에 답이 오는 같은 모양이 되고, 차이는 블록 안이 비었는지뿐입니다. 덕분에 생각을 끄는 방법이 두 가지 생깁니다. 첫째는 사용자가 /no_think를 쓰는 방법으로, 모델이 스스로 빈 블록을 출력하고 답하며 대화 중 턴마다 바꿀 수 있습니다. 둘째는 개발자가 enable_thinking=False로 빈 블록을 미리 채워 넣는 방법으로, 모델은 답부터 쓰고 항상 꺼집니다. 기본은 thinking이라 flag 없는 샘플도 thinking으로 섞습니다.

## @last-flag
여러 턴 대화에서는 flag가 섞일 수 있습니다. 학습 때 flag를 무작위로 여러 개 넣고, 마지막 flag를 따르게 했습니다. 예시의 마지막 질문처럼 no_think 뒤에 think가 오면 생각합니다. 이 능력을 재는 게 in-house 벤치 ThinkFollow로, flag가 섞인 여러 턴 대화에서 매 턴 모드를 맞게 바꾸는지 봅니다. 32B 기준 Stage 3 뒤 88.7이고, Stage 4 General RL을 거치면 98.9로 거의 완벽해집니다.

## @budget
두 모드를 다 배우면 덜 끝난 생각으로도 답할 수 있게 됩니다. 이걸 이용한 게 생각 예산입니다. 예를 들어 예산을 1000 토큰으로 두면, 추론 서버가 토큰 수를 세다가 생각이 1000 토큰에 닿는 순간 강제로 멈추고, 시간이 부족하니 지금까지 생각으로 답하겠다는 문장과 think 닫는 태그를 넣습니다. 그러면 모델이 최종 답을 씁니다. 저자들은 이 능력을 따로 학습하지 않았고 Fusion에서 저절로 생겼다고 말합니다. 참고로 예산은 chat template이 아니라 API 쪽 thinking_budget 파라미터로 다룹니다.

## @fig2
Discussion의 Figure 2입니다. 235B에서 생각 예산만 1K부터 32K까지 바꿨습니다. 네 벤치 모두 꾸준히 오르고, 그림으로 읽으면 AIME'24는 약 42에서 87입니다. 저자들은 32K를 넘기면 더 오를 거라고 봅니다.

## @rl-general
Stage 4 General RL입니다. 20개가 넘는 태스크에 각각 보상을 붙여 두 모드를 함께 다듬습니다. 지시와 형식 따르기, 사람 선호, 에이전트의 도구 호출, RAG 같은 특수 상황이 대상입니다. 보상은 규칙, 참조답을 보고 채점하는 모델, 그리고 RM 세 가지를 씁니다. 그 결과 32B의 모드 전환 정확도 ThinkFollow가 88.7에서 98.9로 올랐습니다.

## @eval-summary
평가는 다섯 축으로 두 모드를 따로 잽니다. 저자 요약은 세 줄입니다. 235B는 두 모드 모두 오픈 모델 최고, 32B는 이전 추론 모델 QwQ를 넘고, 작은 모델들은 증류 덕분에 같은 크기보다 낫다는 것입니다. 샘플링 설정은 모드마다 다릅니다.

## @t11
235B thinking은 DeepSeek R1을 23개 중 17개에서 앞섭니다. 표에서 세어 보면 정확히 17개입니다. 수학, 코딩, 에이전트에서 앞서고, GPQA처럼 지식 위주 벤치는 근소하게 집니다.

## @t12
같은 235B를 non-thinking으로 쓰면 GPT-4o를 18개에서 앞섭니다. 예외로 BFCL은 4.5점 낮습니다. 같은 모델도 AIME가 85.7에서 40.1로 떨어집니다. 생각 여부가 어려운 수학에 얼마나 중요한지 보입니다.

## @t13
32B thinking은 QwQ 32B를 17개에서 앞섭니다. 진 것 중 CodeForces는 5점 차이로 거의 같습니다. o3-mini medium과는 비슷한 수준입니다.

## @t14
32B non-thinking은 두 배 큰 Qwen2.5 72B와 비교합니다. 일반 태스크 네 개는 2승 2패로 비슷하고, Arena-Hard나 AIME처럼 정렬과 추론에서는 크게 앞섭니다. 전체로는 18개 우위입니다.

## @t22
Table 22는 같은 32B 모델을 단계마다 잰 표입니다. 먼저 3단계를 보면, 생각 모드에서 CounterFactQA가 10.9, LengthCtrl이 8점 오릅니다. ThinkFollow 88.7은 모드 전환이 생겼다는 뜻입니다. 대신 AIME와 LiveCodeBench는 1~2점 떨어집니다. 4단계 General RL을 거치면 ToolUse가 15점, ThinkFollow가 98.9까지 오르고, AIME는 다시 조금 내려갑니다. 저자들은 범용성을 위해 이 손해를 받아들였다고 씁니다.

## @summary
정리하면, Qwen2.5의 핵심은 SFT 확장입니다. 학습 설정은 Qwen2와 같고 데이터를 두 배로 늘리며 긴 생성, 구조화 데이터, system prompt 같은 영역을 새로 넣었습니다. Qwen3의 핵심은 thinking mode와 thinking budget입니다. 한 모델에서 flag로 생각을 켜고 끄고, 예산으로 생각 길이를 자를 수 있으며, 예산을 늘릴수록 점수가 오릅니다. 그 대가로 일반 능력은 오르지만 어려운 추론은 조금 내줍니다.

## @open-q
마지막으로 같이 이야기해 볼 질문입니다. Cold Start를 작게 한 게 정말 나은지, 빈 블록 대신 별도 토큰이었다면 어땠을지, 강제 중단 문장이 꼭 필요한지, Qwen2.5의 system prompt 제어와 Qwen3 flag 제어는 무엇이 다른지입니다. 그리고 최근 Qwen3.8과 DeepSeek V4.1은 한 모델을 유지하면서 enable_thinking과 effort 단계로 조절하는데, 한 모델이 나은지 분리가 나은지, flag가 아직 필요한지도 같이 생각해 볼 만합니다.
