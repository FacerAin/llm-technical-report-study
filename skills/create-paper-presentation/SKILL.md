# 논문 발표자료 만들기

원문의 주장을 발표자가 설명할 수 있는 메시지·도식·비교로 바꾼다. 기존 목차와 파트 구성이 있으면 유지하고, 각 파트의 실제 내용과 검토된 비중에 맞춰 분량을 배정한다. 디자인 참고 자료의 연구 제안용 목차를 논문 정독 자료에 이식하지 않는다.

## 입력과 출력

입력은 논문 판본·출처, 파트 추출 결과, 발표 범위와 담당자 Markdown, 필요한 표·그림·수식의 원문 위치다. 빠진 범위는 확인 가능한 입력으로부터 제안한다. 사람 검토 상태는 별도 기록한다. 사용자가 미검토 자료의 초안을 요청했다면 진행하되, 내용·분담 승인을 받은 것으로 바꾸지 않는다.

출력은 독립 실행 HTML, 원문과 분석 문서 링크, 실제 화면을 다시 읽고 쓴 피드백이다. 생성 파일의 저장 위치는 사용자의 요청과 저장소 규칙을 따른다. 발표자료 생성은 기존 학습목표·공식 주차 문서의 개편이나 게시를 포함하지 않는다.

## 내용에서 화면으로

1. 기존 목차·핵심 메시지·근거를 읽는다. 목차가 없으면 문제 → 설계·방법 → 실험 → 한계·질문을 기본 흐름으로 삼는다. 파트 개수와 장수를 같게 맞추지 않는다.
2. 각 장에 **하나의 설명할 질문, 답이 되는 제목, 이를 뒷받침하는 근거**를 정한다. 파트 추출의 K ID와 원문 위치를 연결한다. 상세 읽기 지도는 근거 저장소로 남기고 그 문장을 그대로 전부 옮기지 않는다.
3. 구성요소는 입력 → 연산/변경 → 출력과 다음 요소의 관계로 설명한다. 블록의 실제 위치, 공유·분기·잔차 경로가 질문의 핵심이면 선과 위치로 드러낸다. 선은 연산·데이터·학습 중 무엇의 흐름인지 명확해야 한다.
4. 수치 비교는 모델·학습 단계·데이터셋·metric·shot·sampling 조건을 같은 화면에 붙인다. 미기술은 미기술로 유지한다. 표의 값과 직접 산출한 차이는 구분한다. 저자 가설, 관찰, 발표자의 해석은 해당 문장 가까이에 표시한다.
5. 정보에 맞는 배치를 고른다. 절차에는 흐름도, 구조 변경에는 전후 블록, 같은 단위의 비교에는 정량 차트, 설정 조회에는 표가 적합하다. 전체 흐름·도식 중심·비교·참조 배치를 섞되, 기존 순서는 보존한다. 박스의 수나 장식의 양을 품질 기준으로 삼지 않는다.

시각화·근거의 구체 기준은 [design-and-evidence.md](references/design-and-evidence.md)를 사용한다.

## HTML 제작

[deck-shell.html](assets/deck-shell.html)은 밝은 테마, 가로 이동, 목차, 키보드, 읽기 모드, 인쇄를 갖춘 시작점이다. 단일 파일 안에 CSS·JS·코드로 그린 도식을 포함한다. 원문 이미지가 핵심 증거라면 판독 가능한 크기로 인용하고, 자체 도식은 설명용 재구성임을 표시한다.

반복 제작에는 다음 도구를 사용할 수 있다. JSON 형식과 실행 가능한 작은 예시는 [example-slides.json](assets/example-slides.json)에 있다. `body`·`visual`은 작성자가 검토한 HTML 조각이다.

```sh
python3 scripts/build_deck.py assets/example-slides.json /tmp/paper-example.html
node scripts/check_deck.cjs /tmp/paper-example.html /tmp/paper-example-check
```

검사기는 Playwright를 사용한다. 기본 모듈 탐색이 안 되면 `PLAYWRIGHT_MODULE`에 설치된 모듈 경로, 필요한 경우 `CHROME_PATH`에 브라우저 실행 경로를 지정한다. 의존성이 없으면 가능한 브라우저 도구로 같은 검사를 수행하고 미수행 항목을 기록한다.

## 실제로 보고 수정하기

전체 슬라이드를 렌더해 흐름·반복·밀도를 보고, 가장 복잡한 도식·표·수식은 원래 크기로 읽는다. 데스크톱, 사용 중인 패널 크기, 휴대폰에서 확인한다. 넘침 검사는 자동화하되 실제로 읽히는지는 화면으로 판단한다. 작은 글자를 더 줄여서 해결하기보다 정보를 나누거나 읽기 모드를 제공한다.

휴대폰과 높이가 낮은 화면에서는 한 장씩 표시하는 읽기 모드를 사용하고, 고정 크기 슬라이드로 축소하는 전환은 숨긴다. 다음 장은 맨 위에서 시작하며, 가로로 넘치는 표·도식에 포커스가 있으면 방향키를 해당 영역의 스크롤에 사용한다.

표본 수치를 원문과 다시 대조하고, 화살표 연결·축·범례·출처 링크·이동·터치 스크롤을 확인한다. 피드백은 **관찰한 문제 → 실제 수정 → 확인 근거 → 남은 한계**로 적는다. 디자인 개선을 요청받았다면 피드백만 제안하고 멈추지 말고 해당 장을 고친 뒤 다시 본다. 자동 검증과 AI 검토는 사람 승인과 구분한다.
