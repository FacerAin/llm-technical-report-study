# 논문 파트별 내용·분량 추출

원문에 근거한 한국어 읽기 지도를 작성한다. 파일 출력은 **다섯 PART로 묶은 근거 원본 Markdown + 같은 내용을 담고 PART 안에서 한 페이지씩 넘기는 밝은 디자인의 HTML 읽기 화면**을 기본으로 한다. 첫 화면은 다섯 PART를 고르는 화면이다. 선택한 PART의 내용만 한 페이지씩 읽으며, 전체 문서를 문서 종류별로 이어 붙이거나 긴 스크롤 문서로 바꾸지 않는다. **내용의 공개 여부, 실제 수행 여부, 읽기 부담은 서로 다른 판단**이다. 빈 파트를 채우거나 다섯 파트의 발표 시간을 균등하게 만들지 않는다.

## 담당자가 바로 사용할 수 있는 읽기 지도

결과의 최상위 구성은 **Architecture & Pre-training → Data & Synthesis → Post-training → Alignment & RL → Background**다. 각 PART 안에서 **질문·핵심 인계 → 범위·분량·상대 부담 → 해당 PART가 주관하는 K ID 상세 근거 → 해당 PART의 공백·읽기 계획** 순으로 읽히게 만든다. 각 PART의 첫 요약에는 `설명할 질문 / 핵심 ID / 필수 원문 근거 / 발표에서 보여줄 산출물 / 경계·선택 심화`를 둔다. HTML에서는 모든 필드를 보존하며 읽을 수 있는 크기의 페이지로 나눈다. 전체 PART의 요약만 연속으로 나열한 뒤 모든 K ID를 한데 모으는 구성을 기본값으로 삼지 않는다. 근거는 정확한 판본의 절·도표·확인된 페이지로 연결한다. 산출물은 해당 질문에 맞는 블록 비교, 데이터 흐름, 조건을 붙인 결과표 등의 **인계 제안**이며 페이지형 읽기 화면을 만든다는 것이 발표자료를 새로 구성하거나 역할·발표 시간을 확정한다는 뜻은 아니다. 상세 상태와 주관 K ID 원장은 해당 PART 안에 둔다. 공동 참조는 주관 PART의 K/E 앵커로 연결하고 같은 근거 블록을 여러 PART에 복제하지 않는다. 입력·판본·전체 확인 범위, 전체 흐름·공통 읽기, 전체 집계, 역할 조정·인계·재검토 기록은 별도의 공통 자료로 둔다.

핵심 방법은 용어를 나열하는 데서 끝내지 말고 **입력 → 연산·변경 → 출력·의미**를 짧게 설명한다. 구조는 어느 위치의 무엇을 바꾸는지, 데이터는 무엇이 어느 학습 단계로 전달되는지, 학습은 어떤 입력·target·보상으로 무엇이 갱신되는지를 드러낸다. 생성 단계와 학습 단계의 입력이 다르면 구분한다. 같은 산출물을 여러 파트가 다룰 때는 전달되는 데이터·모델·신호를 인계 경계로 적는다.

원래 구조나 계승 모델과의 차이는 원문이 뒷받침하는 범위에서만 비교한다. 이해를 돕는 축약식·도식은 근거와 연결한 **설명용 재구성**으로 표시하고, 원문 식이나 검증된 실행 순서처럼 제시하지 않는다. 모든 항목에 같은 도식 형식을 강제하지 않고, 불명확한 연산·target·순서는 공백으로 남긴다.

## 입력과 범위

- 기술보고서 원문/PDF와 정확한 버전, 필요한 공식 자료.
- 기존 주차별 학습목표와 읽기 가이드. 이 저장소에서는 사용자가 지정한 주차의 `docs/weeks/wNN/README.md`, `docs/background/wNN.md`, `docs/background/workload.md`를 찾아 읽는다. 다른 저장소에서는 제공된 입력을 사용한다.
- 출력 위치·형식은 사용자가 지정한 것을 우선한다. 파일 출력이면 같은 폴더에 같은 이름의 `.md`와 `.html`을 만든다. 위치가 미지정이고 파일 출력 요청도 없거나, 사용자가 채팅만 원하면 Markdown을 반환한다. 주간 문서·학습목표를 덮어쓰거나 저장 구조를 새로 정하지 않는다.

필수 입력이 없으면 누락을 밝히고 요청한다. 확인 가능한 부분은 임시 지도로 작성하되 원문 미확인 내용을 확정하지 않는다. 사용자 지정 버전을 최신 버전으로 바꾸지 않는다. 여러 보고서를 비교하면 자료별 버전과 근거를 분리한다.

사용자가 제공한 발췌 범위만으로 진행하도록 지정했다면, 누락된 목표·본문은 문서에 기록하고 그 범위의 부분 지도를 완성한다. 제공 범위의 난도와 논문 전체의 상대 부담을 구분하며, 읽지 않은 파트는 확인 필요로 남긴다.

## 원문 확인과 추출

1. 제목·버전·URL/파일, 학습목표·가이드 경로, 접근한 범위와 빠진 본문/부록을 기록한다. 기존 가이드는 읽기 우선순위이며 논문 사실의 증거를 대신하지 않는다. 서로 다른 절 번호나 설명이 발견되면 불일치로 남긴다.
2. 목차와 본문·부록에서 학습목표 관련 절을 확인한다. 그림·표·수식은 번호와 주변 설명을 함께 확인한다. PDF 쪽수는 **1부터 센 파일 페이지**와 **인쇄 쪽수**를 구분한다. HTML만 읽었으면 페이지를 추정하지 않고 절·소제목·도표 번호를 쓴다. 그림을 직접 보지 않았다면 캡션 확인만 했다고 표시한다.
3. 설명 가능한 하나의 본 보고서 핵심 주제에 `K01` 같은 ID를 부여한다. 새 읽기 지도에서는 외부 원전 읽기를 `E01`처럼 별도 ID로 구분한다. 기존 지도는 인용 연결을 보존하기 위해 ID를 강제로 다시 매기지 않고 외부 항목임을 표시한다. 근거에는 자료 ID, 절/쪽/도표, 짧은 요약, 아래 두 판정 축을 붙인다. 같은 주제의 데이터 생성·학습 사용·보상 역할은 연결하되, 서로 다른 질문이면 하위 주제로 나누고 관계를 표시한다. 요약 표의 `[K01](#k01)`은 상세 블록 바로 위의 `<a id="k01"></a>`로 연결하고, 외부 ID도 같은 방식으로 탐색할 수 있게 한다.

### 내용 상태 — 대상 모델·단계·항목별 판정

| 상태 | 판정 근거 |
| --- | --- |
| 원문에 기술됨 | 해당 대상의 방법·데이터·실험이 원문에 설명됨. 일부 설명을 전체 recipe 공개로 확대하지 않음. |
| 기존 모델에서 계승 | 원문이 출발 checkpoint·유지한 구조/방법을 명시함. 계승된 항목과 이번 변경을 분리하고, 선행 모델 세부는 그 원전 확인 후 추가함. |
| 미기술·미공개 | 확인한 관련 범위에서 설명이 없는 **미기술**인지, 저자가 비공개라고 밝힌 **미공개**인지 사유를 덧붙임. 검색·검토 범위를 함께 적음. |
| 미수행이 명시됨 | 저자가 해당 모델/단계에서 하지 않았다고 명시한 근거가 있음. R1-Zero의 초기 SFT 미수행을 R1 전체에 적용하지 않음. |
| 확인 필요 | 원문 접근 실패, 누락된 부록, 버전 충돌, 모호한 대상·단계 등으로 판단 불가. 관련 범위를 읽지 못한 것은 미기술로 단정하지 않음. |

Architecture와 Pre-training을 **각각 판정한 뒤 하나의 파트로 묶는다**. 파트 전체에 상태 하나를 강제하지 말고 항목별 혼합 상태를 요약한다. 계승이 명시된 구조와 미공개인 데이터 조성도 별개 항목이다.

### 주장 성격 — 내용 상태와 별도로 표시

| 구분 | 함께 남길 것 |
| --- | --- |
| 저자 설명·설계 이유 | 무엇을 해결하려고 선택했는지. 효과 입증과 구분. |
| 실험 결과·관찰 | 비교 대상, 데이터/모델/예산 등 조건, 측정값 또는 관찰과 한계. 관찰만으로 원인을 단정하지 않음. |
| 해석·가설 | **저자 가설**인지 **추출자 해석**인지 명시하고 연결 근거와 검증 필요점을 표시. |
| 확인 불가 | 없는 정보와 확인에 필요한 자료. 모호한 사실을 해석으로 채우지 않음. |

## 다섯 파트와 부담

| 파트 | 담당 관점 |
| --- | --- |
| Architecture & Pre-training | 구조와 사전학습을 별도 점검. 학습/실행 시스템을 보조로 맡기는 것은 범위 조정 제안으로 표시. |
| Data & Synthesis | 출처·구성·생성·선별·검증. 어느 학습 단계에 쓰이는지 연결. |
| Post-training | SFT·증류·통합의 모델, 데이터와 학습 target. |
| Alignment & RL | 선호·reward·정책 갱신, 적용 조건과 한계. |
| Background | 이번 목표를 설명하는 데 필요한 선수 개념과 선행·비교 원전. 보고서 자체 내용과 추가 읽기를 분리. |

각 K ID에 주관 파트 하나와 공동 참조 파트를 기록한다. 해당 K 상세는 주관 파트에 한 번만 배치하고, 공동 참조 파트에는 참조 목적과 앵커 링크를 남긴다. 외부 배경 원전도 Background가 주관하는 E ID로 모으고 필요한 파트에서 연결한다. **파트별 핵심 항목 수는 주관 ID 집합 크기**, 공동 참조 수는 별도로 센다. 미기술/미수행/확인 필요 점검 항목은 공백 목록에 남기고 읽을 핵심 항목 수에 넣지 않는다. 계승 설명은 셀 수 있지만 새 기여로 세지 않으며, 외부 배경 읽기는 별도 집계한다.

부담은 `낮음/중간/높음/판단 보류`로 상대 비교한다. 선택한 고유 읽기 범위, 핵심 ID 수, 수식·실험 밀도, 선수지식, 외부 원전 부담을 근거로 적는다. 같은 페이지/절과 공통 읽기는 합집합으로 집계하며, 부분 읽기의 접촉 쪽수는 정독 분량과 구분한다. 쪽수를 모르면 지정 소절 수나 도표 수로 설명한다. 읽지 못한 범위가 크면 부담을 낮음으로 처리하지 말고 판단을 보류한다. 점수·시간·비율은 측정값처럼 만들지 않는다.

## 결과와 다음 단계

[출력 양식](assets/reading-map-template.md)을 읽고 채운다. 각 PART의 공통 읽기 링크 → 해당 PART 심화 → 필요한 선행·비교 자료 링크를 연결하고, 기존 가이드와 달라지는 범위는 제안으로 분리한다. 새 Markdown도 다섯 PART별로 묶고 H2 PART 제목 앞에 `<!-- part: architecture -->`, `<!-- part: data -->`, `<!-- part: post -->`, `<!-- part: alignment -->`, `<!-- part: background -->`를 사용한다. 별도 공통 자료에는 `<!-- part: common -->`를 사용한다. 요약·분량·공백·읽기와 각 K/E 상세 제목은 H3, 필요하면 H4로 둔다. 같은 PART 마커를 후속 절에서 반복할 수 있으며 렌더러는 이를 같은 그룹으로 모은다. 기존 문서 종류별 Markdown을 갱신하지 않고 렌더할 때도 HTML은 주관 필드와 파트별 행에 따라 다섯 PART로 묶고, 기존 K/E ID·사실·근거를 보존한다. 과다 파트는 주제 이관·선택 읽기·깊이 축소, 적은 파트는 계승 확인·관련 비교 지원·발표 축소를 제안한다. 각 제안에 유지할 학습목표, K ID와 수용 시 부담 변화를 남긴다. 최종 역할·분량은 사람이 정한다.

인계 기본 상태는 **미검토**다. 사람이 검토한 ID·범위·분량만 `검토 완료 범위`에 기록하고, #169 발표자료 Skill에는 그 범위와 근거·유보사항을 함께 전달한다. 자동 검증이나 다른 에이전트의 검토를 사람의 승인으로 바꾸지 않는다. 미검토 결과는 검토용 입력임을 명시한다. 이 Skill은 발표자료를 만들거나 #169의 구현, #171의 저장 구조를 변경하지 않는다.

### 한 페이지씩 넘기는 HTML 읽기 화면으로 출력

Markdown을 근거 원본으로 완성한 뒤 [렌더러](scripts/render_reading_map.mjs)로 HTML을 만든다. 다음 명령의 스크립트 경로는 이 스킬 폴더 기준이다. Node.js와 `marked`가 필요하며, 환경에 이미 있는 패키지를 지정할 때는 `MARKED_MODULE`에 `marked` 모듈의 절대 경로를 설정한다.

```sh
node scripts/render_reading_map.mjs input.md output.html --title '보고서 — 다섯 파트 읽기 지도'
```

[HTML shell](assets/reading-map-shell.html)을 직접 열면 다섯 PART의 구성과 페이지 이동을 체험하는 **양식 미리보기**가 표시된다. 실제 논문 결과는 위 렌더러로 생성한 HTML로 전달한다. 양식 미리보기를 논문 추출 결과로 대신하지 않으며, 화면에 내부 치환 표시가 노출되지 않는지도 확인한다.

HTML은 **한 번에 한 페이지만 표시하는 페이지 모드**가 기본이다. PC와 모바일 모두 같은 기본 동작을 사용한다. 전체 문서를 아래로 이어 붙이는 방식으로 바꾸지 않는다. 별도 연속 읽기 모드를 제공하더라도 사용자가 선택했을 때만 켠다.

- 첫 화면에서 다섯 PART를 선택할 수 있게 한다. PART 선택이 최상위 탐색이며 다섯 탭은 원래 순서로 고정한다. 공통 자료는 다섯 PART와 구분한 보조 링크로 접근한다. 요약/상태표/상세 근거 같은 문서 종류를 최상위 그룹으로 사용하지 않는다.
- **첫 파트 선택 화면에서도 하단 이동 조작부를 숨기지 않는다.** 읽기 시작 버튼과 파트 선택을 표시하고, 시작하면 해당 PART의 첫 페이지와 이전·다음·페이지 수로 전환한다. PC·모바일에서 스크롤하기 전에도 조작부가 화면 하단에 보여야 한다. 초기 화면의 오른쪽 방향키로도 읽기를 시작할 수 있다.
- 이전/다음 버튼, `←`/`→`, `Home`/`End`, 페이지 선택 목차는 **현재 PART 안에서만** 이동한다. `현재 페이지 / 현재 PART의 전체 페이지 수`를 표시하고 현재 PART의 제목을 계속 보여준다. 마지막 페이지에서 다른 PART로 자동 이동하지 않는다. PART를 바꾸는 조작은 별도로 제공한다. 입력창·선택창·편집 가능한 요소에 포커스가 있을 때는 페이지 이동 키를 가로채지 않는다.
- 각 PART는 **질문·핵심 인계 → 범위·분량·상대 부담 → 주관 K ID 상세 → 공백·읽기 계획** 순서로 만든다. 공백만 있는 PART도 그 사실과 검토 범위·필요한 읽기를 보여주며 생략하거나 허구의 핵심 항목을 채우지 않는다. 공통 자료에는 입력·판본·전체 확인 범위, 전체 흐름·공통 읽기, 전체 집계, 역할 조정·인계·재검토를 둔다.
- 큰 절 하나를 통째로 긴 페이지에 넣지 말고 요약 카드, 핵심 주제, 표의 의미 있는 행 묶음 단위로 페이지를 나눈다. 긴 주제는 제목과 연속 관계를 표시하며 나누고, 작게 축소하거나 내용을 생략해서 맞추지 않는다.
- `[K01](#k01)` 같은 링크를 누르거나 해당 해시로 직접 열면 **대상의 주관 PART와 해당 페이지를 함께 활성화**하고 근거 위치로 이동한다. 공동 참조에서 이동해도 현재 PART 표시·목차·페이지 수가 대상 PART에 맞게 바뀌어야 한다. 기존 K/E ID, 원문 링크와 관련 파일 링크를 보존한다.
- 한국어 줄바꿈, 밝은 회색 배경·흰 본문·절제된 강조색, 넉넉한 간격과 명확한 제목 위계를 적용한다. 원래 표의 질문·핵심 ID·필수 근거·산출물·경계와 본문의 주장 성격, 조건·유보사항, 설명용 도식의 경계를 모두 보존한다. 작은 화면의 넓은 표는 해당 영역만 가로 스크롤하게 하며, 페이지 이동 조작부는 계속 사용할 수 있게 한다.

페이지형 UI는 추출 내용을 읽는 방식이다. 별도 발표 스토리를 만들거나 추출 내용의 범위를 바꾸지 않는다. Markdown은 계속 수정·재사용 가능한 근거 원본으로 남긴다.

최종 확인: 각 PART의 시작 요약에서 담당 질문·필수 근거·산출물을 찾을 수 있는지, 핵심 기술의 기능과 파트 간 연결이 설명되는지 확인한다. 이어 다섯 파트 유지, Architecture/Pre-training 별도 판정, 핵심 ID 수 재계산, 공백의 검토 범위, 근거의 버전·위치, 저자/추출자 해석 구분, 중복·외부 읽기 분리, 조정안과 검토 상태를 확인한다. 파일 출력 시 실제 HTML을 PC와 모바일 너비로 열어 초기 다섯 PART 선택 화면, 고정 PART 탭·별도 공통 자료, PART 선택 후 한 페이지만 표시되는 상태, 각 PART 내부의 이전/다음·방향키·Home/End·목차 이동과 페이지 수, 편집 가능한 요소의 키 입력을 검증한다. 모든 K/E 상세가 주관 PART에 한 번만 들어 있는지, 다른 PART의 공동 참조 링크 및 직접 해시 진입이 주관 PART·대상 페이지·목차·페이지 수를 함께 전환하는지도 확인한다. 표·도식·한국어의 잘림, 조작부 가림, 외부 원문·관련 파일 링크도 확인한다. Markdown과 모든 HTML 페이지의 내용을 대조해 분할 과정에서 누락이 없는지 확인하고, 실제 수행한 검토·발견 후 수정·남은 한계를 양식 끝에 기록한 뒤 HTML을 다시 렌더한다. 열어보지 않은 화면이나 확인하지 않은 원문까지 검토 완료로 기록하지 않는다.
